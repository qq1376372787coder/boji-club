# 全局组件规格体系 v1（界面设计 · 2026-11-09）

用户指出根子问题：**不是哪一页丑，是整个 App 没有一套规矩**——按钮大小随缘、组件各画各的，首页再顺眼也救不了设置页和资料填写页。
本文件 = **唯一规格表**。全 App 组件尺寸只允许本表的档位，超出即违规。苹果开发照表改造，测试验收照表走查。

---

## 一、先摆现状（为什么要立规矩）

用 grep 统计当前源码（`*.swift`），问题很具体：

| 项 | 现状 | 问题 |
|---|---|---|
| 自定义按钮样式 | **15 个**：`BojiButtonStyle`、`BojiCircleButtonStyle`、`BojiPressableButtonStyle`、`BojiRowPressStyle`、`BojiPressStyle`、`PrimaryButton`、`SecondaryButton`、`DestructiveButton`、`ClubIconButtonStyle`、`ClubActionButtonStyle`、`ClubSelectionButtonStyle`、`ClubMotionButton`、`FlowButtonStyle`、`ClubNativeGlassButtonModifier` 等 | 同一个「主按钮」有 4～5 种写法，视觉各不相同 |
| 系统按钮样式 | 6 种混用：`.bordered` / `.borderedProminent` / `.glass` / `.glassProminent` / `.plain` / `.borderless` | 页面层随意选，没有唯一入口 |
| 高度值 | **13 种**：30 / 32 / 38 / 40 / 42 / 44 / 46 / 48 / 52 / 54 / 56 / 60 / 64 | 相邻页按钮差 2～4pt，看着就是「随缘」 |
| 间距体系 | **两套并存**：`BojiSpace`（18/18/18/14/6/8/12/24）+ `BojiLayout`（pageInset/rowGap/cardInset/blockGap/sectionGap/inline/tight） | 同一个 18 有两个名字，改起来各改各的 |
| 字号 | `BojiFontRole` **9 档**（40/30/28/20/18/17/16/14/13）+ 页面散写 `system(size:)` 52/64/72/74/88 | 排印无层级，越改越乱 |

**结论**：不是审美问题，是**没有唯一规格**。下面把它拧成一套。

## 二、唯一规格表（全部组件只许用这些档位）

### 2.1 按钮 —— 只有 2 种 + 1 种图标钮

| 代号 | 名称 | 高度 | 形态 | 实现 | 用法 |
|---|---|---|---|---|---|
| **B1** | 主按钮 | **54pt** | 玻璃胶囊，全宽（或右侧固定宽） | `clubNativeGlassButton(prominent: true)`；文字 17pt/semibold | **每屏唯一**，一个屏只允许一个 |
| **B2** | 次按钮 | **44pt** | 描边胶囊 | `.buttonStyle(.bordered)` + `.buttonBorderShape(.capsule)`；文字 15pt | 可多个，但不得与 B1 同权重并排 |
| **B3** | 图标钮 | 视觉 **44×44** | 圆形/胶囊，系统符号 17pt | `.buttonStyle(.borderless)` | 返回、关闭、更多、加减 |

**硬规则**
- 除 B1/B2/B3 外，**不得新增按钮样式**；现有 15 个自定义样式全部收敛到这三个入口，其余删除（可保留语义化薄封装，但内部必须产出上述三种之一）。
- 页面层**禁止**直接写 `.buttonStyle(.borderedProminent)` / `.glass*` / `.plain`，一律走统一入口。
- 同一屏内 B1 高度必须一致（54），B2 必须一致（44）。
- 文字按钮（链接）不算按钮：15pt、品牌色、无背景，同屏 ≤2 个，不得替代 B1。

### 2.2 行高 —— 只有 2 档

| 代号 | 高度 | 用途 |
|---|---|---|
| **R1** | **44pt** | 单行入口、设置项、列表行（无副标题） |
| **R2** | **56pt** | 双行入口、卡片头（标题 + 副标题） |

**硬规则**：行高只能是 44 或 56。禁止 30/32/38/40/42/46/48/52/60/64。图标 20pt 居中左对齐，右侧箭头 13pt，左右内边距 20。

### 2.3 输入框 —— 只有 1 种

| 项 | 规格 |
|---|---|
| 高度 | **48pt**（单行）；多行框最小 96pt |
| 圆角 | **12pt** continuous |
| 底色 | `BojiColor.inputSurface`（不透明，不套玻璃） |
| 内边距 | 左右 16、上下 12 |
| 字号 | 17pt（跟随系统 Dynamic Type） |
| 聚焦 | 系统光标 + 系统键盘；**不自绘键盘、不自绘光标** |
| 键盘工具条 | 每个页面**只挂一次** `ToolbarItemGroup(placement: .keyboard)`，含「收起」 |

### 2.4 字号 —— 只有 5 档

| 档 | 字号/字重/字距 | 用途 | 是否随系统缩放 |
|---|---|---|---|
| **T1** 展示 | **88pt** / heavy / -3 | 关键状态分、完成组数、当前重量（每屏最多 1 处） | ❌ 固定 |
| **T2** 标题 | **28pt** / bold / -0.8 | 页面主标题、卡片大标题 | ✅ |
| **T3** 强调 | **17pt** / semibold / -0.2 | 行标题、按钮文字、强调正文 | ✅ |
| **T4** 正文 | **15pt** / regular / 0 | 说明、正文、副标题 | ✅ |
| **T5** 标签 | **11pt** / medium / +0.4 | 字段标签、eyebrow、单位、角标 | ✅ |

**硬规则**
- 全 App 只允许这 5 档；**禁止页面散写 `system(size:)`**（52/64/72/74 等一律归 T1 或 T2）。
- T1 每屏最多一处，且不随 Dynamic Type 缩放（版式元素）；AX 尺寸下 T1 降 48pt。
- 挨着的两档差 ≥2pt 才能同时出现，避免 17/18 这种肉眼不分又互相打架的组合。

### 2.5 间距 —— 只有 3 档

| 代号 | 值 | 用途 |
|---|---|---|
| **S1** 行内 | **8pt** | 同一行内元素间距、图标与文字 |
| **S2** 页边 | **20pt** | 页面左右边距、卡片内边距、输入框内边距 |
| **S3** 区块 | **24pt** | 区块之间、卡片之间、模块上下 |

**硬规则**
- 只用 8 / 20 / 24。禁止 6/12/14/18 等散值。
- 现有两套间距体系（`BojiSpace` 与 `BojiLayout`）**合并为一套**，旧名保留为指向新值的别名，避免一次性大改；新代码只许用新名。
- 列表底部预留 = B1 高度 54 + S3 24 = **78pt**（有 tab 栏再叠，一律 `.safeAreaInset`）。

### 2.6 指标值组件 MetricValue（跨页一致唯一解）



**问题**：同一个数字在首页是 T2 28、在日报是 16，用户翻一页数字缩小一半——这是「不整体」最直接的来源。
**解法**：抽一个组件，五页共用，尺寸写死。**不许页面各自拼数字。**

| 项 | 规格 |
|---|---|
| 结构 | 数字（T2 28 semibold 等宽）+ 单位（T5 11 textTertiary）+ 标签（T5 11 textTertiary）+ 上下 0.5pt 发丝线 |
| 数字 | **T2 28 / semibold / 等宽 / 字距 -1** |
| 单位 | T5 11，紧跟数字 baseline 右侧 |
| 标签 | T5 11，在数字上方 |
| 分隔 | 上下各一条 `BojiLayout.hairline`（0.5） |
| 空值 | **不渲染该块**（不是显示 0/—） |
| 用在哪 | 今天页、日报、周报、记录页、身体页——**同名指标五页同一档** |

**布局两种，别混（施工歧义已消）**
| 场景 | 分隔线怎么放 |
|---|---|
| **横排三个**（首页三指标） | 外层**上、下各一条** 0.5pt；**块与块之间一条 0.5pt 竖线**（不用每条块各画上下线，否则出现双线） |
| **单列多行**（记录/日报明细） | 每块**下一条** 0.5pt，整列顶部一条；块与块不重复叠线 |

**字重的例外（写死，免争议）**
- `MetricValue` 里的**数字**：T2 28 / **semibold**（数据要读得清但不抢主标题）。
- 页面里作为**标题**用的 T2 28：**bold**（如空态短标题「今天练上肢推」）。
- 同档不同字重是**刻意**的：数字用 semibold 让位给行动，标题用 bold 承担主角。除此以外 T2 只许这两种字重。

**白名单**：身体页的体重巨号（T1 88）是**该页唯一主角**，允许不同于日报；除此之外任何页面的同名指标**必须 T2 28**，差一档即违规。

**根因提醒**：`BojiTypeRole` 里 `.body`(16)/`.display`(34)/`.section`(20) 与 `BojiFontRole` 里 `.bodyMetric`(40) 都是规格表外的历史档位。**甲-2/甲-3 必须把它们收进 T1–T5**，否则跨页一致性永远对不齐——只改页面不改档位，下次还会散。

### 2.7 日报页层级裁决（产品经理提问，界面设计定）

日报是**阅读页**，不是数据页。层级如下，避免与数据条撞档：

| 元素 | 档位 | 说明 |
|---|---|---|
| 导航标题 | `.inline` | **不用大标题**——把唯一的 T2 让给数据条，避免两个 28 撞档 |
| 日期/副标题 | T5 11 | 首行 |
| 指标数据条 | **T2 28 semibold**（走 MetricValue） | 与其它四页一致 |
| 数据条标签 | T5 11 | 卡标签不再是"标题"，只是小标签 |
| 段落标题（训练/营养/恢复） | **T3 17 semibold、textSecondary** | 用字重 + 颜色与数字区分，不靠字号抢 |
| 正文 / 结论句 | T4 15、行距 1.55 | 阅读主体 |
| 建议/提示 | T4 15、textSecondary | — |

**一句话**：日报每屏只允许一组 T2（数据条），段落靠 T3 + 颜色分层；**不许再出现第二个 28 档元素**（包括大标题）。

### 2.8 圆角 —— 只有 3 档

|---|---|---|
| **C1** | **24pt** | 卡片、视频带、弹层 |
| **C2** | **12pt** | 输入框、小色块、组次块 |
| **C3** | **999** | 胶囊按钮、标签 chip |

全部 `continuous`。

### 2.9 G-1 管辖范围与「族」定义（2026-11-09 裁决，解决判据无边界）

**问题**：G-1 原文「只允许 44/48/54/56 ∪ 58」按字面套全库，连 `width == height` 的图标、头像、图表容器、`TextEditor` 都被判违规——**判据没界定管辖范围，等于分母没定，永远过不了**。按族登记，不逐条列。

| 族 | 范围 | G-1 是否管 | 规则 |
|---|---|---|---|
| **族 1 · 图元** | `width == height` 的图标、头像、照片、动画帧、圆点 | **不管** | 按尺寸族走，但**同类图元必须同尺寸**（这才是规格初衷：一致性，不是统一到 44） |
| **族 2 · 可视化容器** | 图表、热力条、地图、视频渐隐层 | **不管** | 容器自适应 + 允许 `minHeight`，不进控件档位 |
| **族 3 · 多行输入** | `TextEditor` / 多行文本框 | **不管** | `minHeight` 100–160，随内容增高 |
| **族 4 · 展示字行盒** | 巨号所在行、T1/T2 文本自身行盒 | **不管** | 高度跟随字号，不套 44/56 |
| **命中区补偿** | `.contentShape(inset)`、`.padding` 撑出的命中区 | **不算控件高** | 视觉高度与命中区分离是 iOS 正解 |
| **族 5 · 内容块** | 含多元素的卡片/区块（动作块、提示块、图表占位卡、带进度段的行组） | **不管** | 高度随内容与内部元素自适应；**只要求内部元素各自合规**，不要求块本身落在 44/56 |
| **族外清单** | 分隔线（1/3/4/6/24/28）、渐隐层、插画、导出画布、展示字行盒 | **不扫** | 这些不是控件也不是容器，扫描器应排除，避免下次又被当违规 |
| **G-1 实际管辖** | **按钮、输入行、选项行、日历格、入口行** | **管** | 只许 **44 / 48 / 54 / 56** |

**含图入口行的定式（`TrainingPreviewView:79` 类问题）**：入口行仍是 **R2 56**；**行内图元 44**（不是 56）＋**垂直内边距 6**×2 = 正好 56。**不要为图元开新行高档，也不要让图元撑破行高——图元服从行高，不是行高服从图元。**

**例外白名单（只能在明处）**

| 位置 | 高度 | 理由 |
|---|---|---|
| 训练中底部玻璃坞 | **58** | 同时容纳计时与主操作，54 放不下 |
| 登录页 Apple 按钮 | **48** | 苹果系统规范优先（不是 52，代码向 48 对齐） |
| `NativeData134.swift:158` 时间线连接线 | 52 | 竖线元素，非控件 |
| `BojiComponentGalleryView:48` 色板 | 52 | 组件画廊演示，非产品界面 |
| `ClubAIShell:1122` 视频渐隐层 | 60 | 纯装饰渐变，非控件 |
| `ProductArchitecture:806` 图表容器 | 52 | 族 2，可视化容器 |

**遗留裁决**：`ProductArchitecture:199`（`minHeight: 78` 三行训练入口）——**归 R2 56，第三行内容压成两行**（标题 + 一行副标题）。行高只有 44/56 两档是硬纪律，**三行说明是「信息没归置好」，不是需要第三个行高**。若确实压不下，删掉最不重要的那行。

> **78 → 56 怎么装得下（测试验收 已确认它是 Button 入口行，同族先例 `PlanManagement:59` 64 已归 56）**：
> 图标 **34 → 28**（图元族允许独立尺寸）＋ 标题 **T3 17** ＋ 副标题 **T5 11**（行高合计约 30）＋ 垂直内边距 **8×2** = 约 46，**56 内有富余**，不需要压缩字号也不需要新开档位。三行里的第三行（说明文字）并进副标题或删掉。

## 五、施工方式（不改业务逻辑，只收口）

1. **先建 3 个统一入口**（`BojiButton.primary/.secondary/.icon`、`BojiRow`、`BojiField`），内部产出上表尺寸；
2. **逐页替换**：先把 15 个旧样式改为指向新入口（薄封装，行为不变），页面代码尽量不动；
3. **删散值**：全库 grep `frame(height:` `minHeight:` `system(size:` `padding(.bottom,` 等，把非规格值逐个归位；
4. **一批一编译**，每批出截图（23 页 × 亮/暗/AX）；
5. 走查按本表逐页核：按钮是否只有 3 类、行高是否只有 44/56、输入是否只有 1 种、字号是否只有 5 档、间距是否只有 3 档。

## 七、同类组件对照表（测试验收「八查」第 8 条的一审工具）

用法：**同一类组件在不同页面的截图横向摆在一起，按本表核像素**。单看一页看不出「随缘」，横向拼才看得见。

### 7.1 按钮类

| 组件 | 出现页面 | 唯一规格 | 判定 |
|---|---|---|---|
| 「开始/开始练/开始这组」 | 首页、训练中 | **B1 54 玻璃胶囊** | 三处高度、材质、圆角必须一致 |
| 「保存」类（保存这一组/保存计划/保存资料） | 记录、计划、资料 | **B1 54 玻璃胶囊** | 同上 |
| 「去连接/下一步」 | 空态、引导、资料 | **B1 54 玻璃胶囊** | 同上 |
| 「取消/上一步/稍后再说」 | 各弹层、引导、登录 | **B2 44 描边** 或 **文字链 T4 15 品牌色** | 二选一，全 App 一致 |
| 「返回/关闭/更多/加减」 | 全页面 | **B3 图标 44×44**，符号 17pt | 命中区不得小于 44 |
| 「通过 Apple 登录」 | 登录 | **系统原生 48**（例外，苹果规范优先） | 唯一允许非 54 的按钮 |

### 7.2 行类

| 组件 | 出现页面 | 唯一规格 | 判定 |
|---|---|---|---|
| 单行入口（设置项、列表行） | 设置、我的、记录、计划 | **R1 44** | 高度必须 44，图标 20 居中，箭头 13 |
| 双行入口（标题+副标题） | 设置、我的、动作库 | **R2 56** | 高度必须 56，副标题 T5 11 |
| 数据条（三指标横排） | 首页、记录、身体、日报 | 数字 **T2 28** + 标签 **T5 11** + 0.5pt 细线 | 数字与标签字号必须统一 |
| 组次块 | 训练中、记录 | **44 高 / C2 12 圆角** | 完成态只变底色，不改尺寸 |

### 7.3 输入类

| 组件 | 出现页面 | 唯一规格 | 判定 |
|---|---|---|---|
| 文本输入框 | 登录、资料、设置、记录 | **48 高 / 12 圆角 / inputSurface 底 / 内边距 16** | 全部一致；不得出现 46/52 |
| 巨号可编辑（重量） | 记录 | **T1 88** + T5 11「重量」 | 点按原地变输入，不跳布局 |
| 步进器 | 记录 | **44×44 方块，C2 圆角** | 加/减各 44 |
| 键盘工具条「收起」 | 全页面 | **每页 1 个** | 计数必须 =1 |

### 7.4 玻璃类（只在操作层）

| 组件 | 出现页面 | 规格 |
|---|---|---|
| 主操作玻璃胶囊 | 全页面 | `clubNativeGlassButton(prominent:true)`，54 |
| 底部坞 | 训练中（唯一例外 58） | 左计时 + 右 B1 44 变体 |
| 输入栏 | AI 会话 | 44 高、C3 胶囊 |
| 庆祝卡 | 训练完成 | C1 24 圆角，全 App 唯一玻璃大卡 |

### 7.5 判定口径

- **通过**：同类组件在 N 张截图里高度、圆角、材质、字号完全一致（允许 ±0），且落在本表档位。
- **不通过**：出现表外尺寸（如 46/52/48 混、40/44 混）即为违规，一票否决。
- **例外白名单**：训练中坞 58、登录 Apple 按钮 48。除此之外无例外。
