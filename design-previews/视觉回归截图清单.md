## 三、能自动断言、不需要人眼的破相（优先做这个）

截图解决了「谁来看」的问题，但更硬的是**用断言把破相钉死**——这类问题有确定判据，写进 UI 测试就能拦住：

| 破相 | 可自动判定 | 断言写法（示意） |
|---|---|---|
| 文本被截断 | 元素 `label` 与实际文案不符 / `value` 含「…」 | `XCTAssertEqual(element.label, "还没同步到")`；对关键串逐字比对 |
| 键盘工具条重复 | 键盘上方「收起」按钮数量 | `XCTAssertEqual(app.toolbars.buttons.matching(identifier:"收起").count, 1)`（G3 判据） |
| 浮条压 tab 栏 | 两元素 frame 相交 | `XCTAssertFalse(bar.frame.intersects(tabBar.frame))` |
| 浮钮盖卡片 | 按钮 frame 与卡片 frame 相交 | 同上 |
| 元素超出屏幕 | frame 超出 `app.windows.firstMatch.frame` | `XCTAssertTrue(win.frame.contains(el.frame))` |
| 报错未操作就出现 | 首屏不应存在错误文本 | `XCTAssertFalse(app.staticTexts["暂时未能完成操作，请稍后重试"].exists)` |
| 主操作不唯一 | 同屏 54pt 主按钮数量 | 用 identifier 计数 `== 1` |

**建议**：上面 7 条各写一个断言，比人眼可靠，且回归零成本。测试验收 说的 `grep` 两条（工具条挂载次数、硬编码 padding）= 源码级一半，这些是运行期另一半。

## 四、落地步骤（给苹果开发）

1. 新建 `BojiClubUITests/VisualRegressionShots.swift`（或用截图模式跑现有用例）：
   - 一个 `testCaptureAllScreens()`，按 R01–R16 顺序导航，每页调 `shot("R01-home-data")` 这类固定名；
   - 用 `launchEnvironment` 注入假数据开关（无健康数据 / 有健康数据 两套），R02/R10 靠它；
   - AX 那张用 `app.launchArguments += ["-UIPreferredContentSizeCategoryName", "UICTContentSizeCategoryAccessibilityXXXL"]`；
2. 流水线加一步（`ci.yml` 或新 workflow）：
   ```sh
   xcodebuild test -scheme BojiClub -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
     -only-testing:BojiClubUITests/VisualRegressionShots \
     -resultBundlePath shots.xcresult
   xcrun xcresulttool export attachments --path shots.xcresult --output-path screenshots/
   ```
3. 上传 `screenshots/` 为 artifact，或直接 `git add screenshots/` 推一个小目录（PNG 压缩后每张 200–400KB，16 张约 4MB，可接受）；
4. **交给谁看**：用户 / 有视觉能力的成员看 artifact；我按第三节的断言做程序化走查（我不具备读图能力，这条必须说清，避免又变成"以为有人看过"）。

---

## 五、这条流程解决什么

前两轮的根因不是「改得不对」，是**改完没人真正看过就跑向用户**。接上这条链：
改完 → 云端自动截图 + 自动断言 → 图与断言都过了才出包 → 用户装机。
用户不会再当第一个看到界面的人。
