# 阶段 6 · 导航壳原生化迁移方案（苹果开发 · 2026-11-08）

方案 2+3 混搭第一批的壳层改造设计。等三屏视觉稿期间完成技术准备，稿到即动工。

## 一、现状（已核实）

- `ClubAIShell.swift:296-317` `navigationWorkspace`：`NavigationStack` + `TabView(.page)` 横翻三个工作区（AI 首页 / 训练计划 / 记录三分类），无原生 tab bar。
- `ClubAIShell.swift:782` `ClubModeCapsulePicker`：自绘胶囊分段，放系统工具栏 principal 位——用户点名「不是原生组件」的部位。
- 工作区状态：`mode: ClubShellMode`（clubAI/training/records(分类)）+ `workspacePage: ClubShellPage`，外置保存（切走不丢滚动锚点）。

## 二、目标结构

```
外层 TabView（原生 tab bar，iOS 26 自动悬浮玻璃）
├─ tab「今天」→ NavigationStack { aiWorkspace }        ← 现主壳 AI 首页
├─ tab「训练」→ NavigationStack { ClubPlanHub }        ← 现训练工作区
└─ tab「记录」→ NavigationStack { TabView(.page){ 记录三分类 } }  ← 横翻手势保留在记录页内部
```

- tab 图标/标题用系统 SF Symbols + 中文短词（「今天 figure.heart.text.message」「训练 figure.run」「记录 chart.bar.doc.horizontal」，最终以视觉稿定）。
- `ClubModeCapsulePicker` 与外层 `ClubShellPage` 横翻删除；`mode` 与 tab `selection` 单向绑定。
- 底部坞（训练恢复条）移到对应 tab 的 `safeAreaInset`，仍走 `clubGlassGroup`。

## 三、状态迁移与回归清单

| 风险点 | 处置 | 回归验证 |
|---|---|---|
| records 三分类横翻（`pageCategories` ForEach） | 移入「记录」tab 内部 `TabView(.page)`，手势不丢 | 三分类左右滑切换 + 分类落点保持 |
| 训练滚动锚点 `trainingScrollAnchor`/`calendarExpanded`/`selectedDate` | 仍外置存于 Shell，切 tab 不重置 | 切走切回锚点不变（现有 20 次切换用例口径） |
| `mode` 状态机（侧栏路由/深链都写 mode） | `mode` 保留为唯一事实，tab selection 双向同步 | 深链进记录/训练、侧栏跳转仍正确 |
| 无障碍 identifier（v2-sidebar-toggle 等） | 全部保留；新增 tab 元素 identifier | UI 测试引用不破 |
| 训练中 bottomDock | 移到各 tab `safeAreaInset` 或 Shell 顶层（视觉稿定） | 训练中切 tab 恢复条跟随 |
| iOS 17 兼容 | 原生 TabView 全版本可用；iOS 26 悬浮玻璃由系统自带，无需页面写 #available | 17/26 双端 |
