# BOJI_CLUB 全页面新蓝图 v1（产品经理 · 2026-11-09）

> **总原则：每一屏只回答一个问题，只有一个主操作。**
> 用户在任何一个屏幕上，2 秒内能回答：「这一屏要我干什么？」
>
> **主角法则**：每屏最大的那个字，必须是「用户此刻的目标」，不是「系统的度量」。
> 例：首页最大字 = 「今天练上肢推」（他的目标），不是「72 状态分」（我们的度量）。

---

## 〇、五个根本性改动（和现在比，变了什么）

| # | 现在 | 之后 | 为什么 |
|---|---|---|---|
| 1 | 首页是**仪表盘**（状态分当主角，信息平铺） | 首页是**今天的一页纸**（今天练什么当主角） | 用户打开是有事，不是来逛 |
| 2 | 训练中**列表 + 坞 + 菜单**堆一屏 | 训练中**一屏一组**，只回答这一组 | 练的时候脑子里只装得下一组 |
| 3 | 记录 tab 是**分类入口**（选训练/饮食/身体/报告） | 记录 tab 是**今天的时间线**（按时间倒序） | 用户想看"我记了什么"，不是"选分类" |
| 4 | 日报是**报告**（读的多，做的少） | 日报是**明天的行动单**（每条建议带应用按钮） | 用户要的不是分析，是下一步 |
| 5 | 成长季/任务中心/洞察时间线/AI 对话**占首页与导航** | 全部**收进「更多」**，首页不放 | 功能密度超载是"乱"的第一因 |

## 五、记一餐（三步）

**这一屏回答：这餐吃了什么、多少？**

**第 1 步 · 拿到食物**
```
┌─────────────────────────┐
│ ‹      记一餐            │
│                         │
│  ┌───────┐ ┌───────┐   │
│  │  拍照  │ │  说一句 │   │  两个大入口
│  └───────┘ └───────┘   │
│  ┌───────────────────┐  │
│  │ 搜索食物           │  │
│  └───────────────────┘  │
│                         │
│  常吃：燕麦鸡蛋 / 鸡胸饭  │  ← 最近 3 条，一点就填
└─────────────────────────┘
```

**第 2 步 · 确认份量（识别结果 + 份量同屏）**
```
┌─────────────────────────┐
│ ‹      确认              │
│                         │
│  燕麦鸡蛋                │  T3 17
│  420 kcal · 蛋白26g      │  T5 11
│                         │
│  份量  ──●────  1 份     │  ← 拖一下就行
│                         │
│  这一餐：420 kcal        │  T2 28
│ ─────────────────────── │
│ ✓ 早餐  ✓ 午餐  ✓ 晚餐   │  默认按时间自动选
│                         │
│ ╔═════════════════════╗ │
│ ║     保存             ║ │  B1
│ ╚═════════════════════╝ │
└─────────────────────────┘
```

**主操作**：保存
**步数**：拍照 → 确认 → 保存 = **3 步**（份量默认 1 份，不改直接存）
**数据来源**：识别结果 / 食物库 / 常吃记录
**入口**：记录页「记一餐」、训练完成页「记一餐」、首页「记一餐」
**出口**：保存后回记录时间线，新条目高亮 1 秒

**关键**：**默认值必须准到用户不用改**。份量默认 1 份，餐次按时间自动判——不让用户做多余选择。

## 十五、空态（全局规则）

**每一处空态 = 一句说明 + 一个动词按钮。**

| 场景 | 文案 | 按钮 |
|---|---|---|
| 今天没计划 | 今天还没有安排 | 生成计划 |
| 今天没记录 | 今天还没记吃的 | 记一餐 |
| 没有体重 | 还没有体重记录 | 记体重 |
| 没有健康数据 | 连上健康，这里会有数据 | 去连接 |
| 没有报告 | 记录后第二天出第一份日报 | 去记一餐 |
| 搜索无结果 | 没找到这个动作 | 清除筛选 |

**禁止**：纯插图、纯灰字、"暂无数据"、报错原文。

```
│  [ 重试 ]                │  B2 44

```

**禁止**：`Error Domain=` / `The operation couldn't be completed` / 任何系统原文。

## 十七、导航结构（Tab 变化）

| 现在 | 之后 |
|---|---|
| 今天 / 训练 / 记录（3 Tab） | **今天 / 记录 / 计划 / 我的**（4 Tab） |

- **今天**：该干什么（首页）
- **记录**：记了什么（时间线）
- **计划**：这周练什么（计划周视图）
- **我的**：设置、会员、更多（成长季/任务中心/AI 对话收到这里的「更多」）

**为什么 4 个**：3 个 Tab 塞不下「今天」和「计划」的区分，用户现在要点"训练"tab 才看到计划，但计划是他的核心资产。

---

## 十八、施工优先级（给开发）

| 批次 | 内容 | 理由 |
|---|---|---|
| **第 1 批** | 今天 + 训练中 + 训练完成 | 主旅程核心，用户每天必经 |
| **第 2 批** | 记录（时间线）+ 记一餐 + 饮食 | 第二高频 |
| **第 3 批** | 计划 + 看结果 + 日报 + 周报 | 需要前面数据支撑 |
| **第 4 批** | 设置 + 会员 + 引导 + 我的 | 低频但必须全新 |
| **第 5 批** | 空态 + 错误 + 全局动效收尾 | 贯穿所有页面 |

## 二十、视觉与动效规格（华丽感 / 高级感 / iOS 原生）

> 用户定调：**符合华丽感、高级感、iOS 原生系统组件、iOS 原生玻璃**。
> 本节 = 每屏「华丽感从哪来」的施工依据。**不另立档位**，全部沿用
> 《全局组件规格体系 v1》（尺寸）与《动效与特效规格》（动效），本节只规定「每屏怎么用」。

### 20.1 五条视觉铁律

| # | 铁律 | 为什么 |
|---|---|---|
| **V1** | **玻璃只在操作层**（B1 主按钮 / 底部坞 / 输入栏 / 庆祝卡），内容层一律不透明 | 内容套玻璃 = 廉价感的头号来源，也是可读性杀手 |
| **V2** | **每屏一个巨号**（T1 88），且必须是「用户此刻的目标」不是「系统度量」 | 高级感的来源是「一个主角 + 大量留白」，不是堆装饰 |
| **V3** | **分层靠 0.5pt 细线，不靠卡片描边阴影** | 细线是编辑部/杂志的语汇；卡片边框是后台管理系统的语汇 |
| **V4** | **动效有层次但不循环**（进/滚/按/数/庆/璃 各司其职，无无限闪动/彩虹轮播） | 华丽 ≠ 吵；一屏同时运动元素 ≤2 |
| **V5** | **三联动同拍**：动效 + 震动 + 音效同时触发，误差 <30ms | 这是"高级"和"廉价"的分水岭——廉价感常来自只动了画面 |

### 20.2 每屏的玻璃件位置（唯一允许清单）

| 屏 | 玻璃件 | 位置 | 说明 |
|---|---|---|---|
| 今天 | B1 主操作「开始练」 | 底部安全区内，54 玻璃胶囊 | 全屏唯一玻璃 |
| 训练中 | B1「记完这组」 | 底部，54 玻璃胶囊 | 组间休息时玻璃淡出、大字接管 |
| 训练中·休息 | 无玻璃 | 整屏大字 + 两个 B2 描边 | **休息是冥想时刻，不加玻璃** |
| 训练完成 | 庆祝层（C1 24 玻璃大卡）+ B1「记一餐」 | 中上 + 底部 | 全 App **唯一**允许的玻璃大卡 |
| 记录 | B1「记一餐」 | 底部 | 时间线本身零玻璃 |
| 记一餐 | 输入栏（C3 胶囊）+ B1「保存」 | 搜索/份量 + 底部 | 两步各一个玻璃件 |
| 饮食 | B1「记一餐」 | 底部 | 进度条不透明 |
| 身体 | B1「记体重」 | 底部 | 折线图不套玻璃 |
| 看结果 | B1「看这周报告」 | 底部 | 三个数据条用细线，不用玻璃 |
| 日报/周报 | **顶部工具条 1 处玻璃**（返回+分享） + B1「应用」 | 顶部 + 底部 | 正文全不透明 |
| 计划 | B1「调整这周」 | 底部 | 周视图不套玻璃 |
| 设置 | **零玻璃**（原生 List） | — | 设置页要绝对清晰 |
| 会员 | B1「开始使用」 + 价格卡描边 | 底部 + 卡 | 价格卡**不透明**（Apple 审核要求） |
| 引导 | B1「下一步」 | 底部 | 每步一个玻璃件 |
| 空态 | B2 44 描边（**不是玻璃**） | 卡内 | 空态按钮让位给主操作 |
| 错误 | B2 44 描边 | 卡内 | 同上 |

**判定**：任何屏出现表外玻璃件 = 违规。**全 App 玻璃件总数应 ≤ 屏数的 60%**。

### 20.3 动效编排（七类，对应《动效与特效规格》M1–M8）

| 类型 | 用在哪几屏 | 规格 | 三联动 |
|---|---|---|---|
| **进**（M3 淡入 + stagger 0.05） | 今天（巨号→清单→按钮）、日报（结论→数→建议）、训练完成（数字逐个滚） | 0.35–0.42s，元素 stagger 0.05 | 无音效（入场不吵） |
| **滚**（M6 视差/收缩） | 今天（顶部大标题收缩成导航标题）、记录（日期吸顶） | 200pt 内走完，只动 transform/opacity | 无（连续滚动不震） |
| **按**（M7 scale 0.97 + 阴影收紧） | 所有 B1/B2 | 0.16s micro | 震动 `pressDown/pressRelease` + 音效 S1 `tap` |
| **数**（M8 counter 滚动 0.35s） | 训练完成三数字、日报三数字、体重变化、状态分（「今天之后」里） | 0.35s，等宽数字 | 无 |
| **庆**（celebrate 0.52/0.74 + stagger） | **只在训练完成**（全组完成 / 保存成功） | 一次性，不循环 | `heavyDrop()` + S4 `workout_done` |
| **璃**（玻璃按压高光随指尖） | 所有玻璃件（系统自带） | iOS 26 原生，不自造 | 与「按」同拍 |
| **转**（M5 空间转场） | 记录条目 → 编辑页、计划卡 → 计划详情 | iOS 18+ `navigationTransition(.zoom)` | 无 |

**训练中专属三联动**（用户点名最有感的一处）：
- 完成一组 → 勾选 bounce + `latch()` 震动 + S2 `set_done` 音效，**同一帧**
- 休息 3/2/1 秒 → 数字微脉冲 + `tick()` 每 3 秒 + S5 `rest_tick`
- 全组完成 → 底部玻璃展开成「这一练完了」+ `heavyDrop()` + S4

### 20.5 动效降级（必须有）

| 设置 | 降级行为 |
|---|---|
| 减少动态效果 | 全部动效 → 0.12s 交叉淡入；巨号直落终值；视差不动；**玻璃按压与三联动保留**（功能反馈不降） |
| 增强对比度 | 玻璃件转不透明 + 1pt 描边；细线加粗至 1pt |
| 降低透明度 | 玻璃件转不透明 |
| 静音开关 | 音效静默，**震动保留** |
| iOS 17（无系统玻璃） | 回退 `BojiGlassFallbackButtonStyle`（磨砂 + 按压缩放 + 阴影收紧） |

### 20.6 华丽感的三条来源（给界面设计/开发对齐审美）

1. **排印张力**：88pt heavy 巨号 vs 11pt 标签 = 8 倍字号差。**落差本身就是华丽感**，不需要装饰。
2. **留白克制**：一屏只有 1 个主角 + 1 个动作，其余全是灰字。**敢空，才显贵**。
3. **动效层次**：进场有节奏（stagger）、滚动有响应（视差）、按压有实感（三联动）、完成有庆祝。**华丽在"响应"里，不在"装饰"里**。

> 反面清单（做了就廉价）：彩虹渐变、无限循环动画、整屏转场、内容套玻璃、投影过重、
> 图标囤积、装饰性粒子、每屏都在动。
