# 数据口径统一表 v1（产品经理 · 2026-11-09）

> 目的：管住「面板和日报对不上」。本文档定义 **每一个对外显示的数字** 的唯一来源、算法、显示位置、空值表现。
> 规则：**一个数字全 App 只允许一个算法**。任何页面要显示，必须复用这里的定义，不得就地重算。
> 本表所有结论均来自源码实读（文件+行号已标），不是推测。

---

## 〇、总则（四条硬规矩）

| # | 规矩 | 判据 |
|---|---|---|
| **G1** | **一个指标，一个算法，一个名字。** 同义不同名（"总容量"/"力量总容量"/"额外负重"）必须合并 | grep 全库同一概念的名字，只能剩 1 个 |
| **G2** | **空值不是 0。** 无数据一律显示「—」或整块隐藏，绝不显示 0、0%、— 混用 | 截图核：空态页无孤立 `0` |
| **G3** | **同一屏幕内的分子分母必须同源同范围。** 不允许"分子按已确认口径、分母按全部记录口径" | 逐条比对分子分母的数据集合 |
| **G4** | **跨页对比必须同口径。** 首页/记录/日报/周报/趋势，同一天同一指标读数必须相等（允许四舍五入到整数后的 ±1） | 见 §六 对账测试 |

## 一、训练量（容量）

### 1.1 定义（唯一口径）

| 项 | 规定 |
|---|---|
| **名称** | **训练量**（全 App 唯一叫法。废除"总容量""力量总容量""额外负重""负重训练量"） |
| **单位** | **kg·次**（重量×次数）。废除裸 `kg`（会被误读成重量） |
| **算法** | `Σ(每组 重量kg × 次数)`，**仅计入**：① 已点完成；② 非计时动作（`durationSeconds == nil`）；③ 属于**已确认保存的训练场次** |

## 三、时长

### 3.1 定义（**三种时长必须分开命名**）

| 名称 | 算法 | 用途 |
|---|---|---|
| **训练时长** | `confirmedTraining.elapsedSeconds / 60`（从开始到结束的墙钟时长，扣除暂停） | 一次训练花了多久 |
| **计时训练时长** | `confirmedTraining.timedSeconds / 60`（计时动作的累计秒数） | 计时动作做了多久 |
| **时长趋势** | 同「计时训练时长」，按桶聚合 | 趋势页 |

> **禁止**：`Models.swift:343` 现在的 `durationMinutes` 逻辑是「有 elapsed 用 elapsed，否则用 timedSeconds」—— 这让同一个字段在不同时刻代表两种含义，日报和周报可能对不上。

### 3.2 代码现状与冲突（实测）

| 位置 | 现状 | 问题 |
|---|---|---|
| `BojiClub/Models.swift:343` | `elapsed > 0 ? elapsed/60 : (timed > 0 ? timed/60 : nil)` | ❌ **一字段两义** |
| `BojiClub/Models.swift:320` | `elapsedSeconds` = `seconds(start,end) - pausedSeconds` | ✅ 正确（扣暂停） |
| `BojiClub/WeeklyReportView.swift:544` | `totalDuration += confirmed.elapsedSeconds / 60` | ✅ 口径对，但**每日独立整除**后累加 → 7 次 90 秒 = 每次 1 分钟 = 7 分钟，实际 10.5 分钟。周报应先累加秒再换算 |
| `BojiClub/TrendAnalysis.swift:503` | `timedMinutes` = `timedSeconds / 60` | ✅ 口径对 |
| `BojiClub/DailyReportView.swift:201` | 显示「训练时长」= `duration_minutes` | ⚠️ 字段来源是 343 行的双义值 |

> **裁定**：
> 1. `duration_minutes` 只放 elapsed（训练时长）；另加 `timed_minutes` 字段给计时动作。
> 2. 周报时长改为**先累加秒、再除 60**（`WeeklyReportView.swift:544`）。
> 3. 界面上「训练时长」和「计时训练时长」不得共用一个标签。

### 5.3 分项 sheet 的定稿形态（与界面设计对齐，2026-11-09 晚）

**三行，每行「标签 T3 17 + 锚点 T5 11 + 分值」**，另加一句解释句：

| 行 | 标签（T3） | 锚点（T5，textTertiary） | 分值 |
|---|---|---|---|
| 1 | 睡眠 | 睡 7.5 小时记 50 分，按实际时长折算 | `42 / 50` |
| 2 | 静息心率 | 65 次/分记 30 分，越高越低，最低也记 8 分 | `18 / 30` |
| 3 | 近三天练过 | 练过记 20 分，没练过也记 6 分 | `20 / 20` |

**解释句（T4 15）**：「就这三项相加。没同步到的那项按 0 分算，其余照常算。」

**三条硬要求（验收时逐条核）**：

1. **分项之和 = 巨号总分**（用户会自己加：42 + 18 + 20 = 80，必须等于巨号）。三项显示值必须都是整数且与总分同源取整。→ **一票否决，见 §5.5**
2. **锚点行必须写明满分线 + 方向**，不能只写"睡够才给分"。睡 5 小时给 33 分（线性），锚点写「睡 7.5 小时记 50 分，按实际时长折算」用户才能自己算。
3. **缺数据的那项必须标出来，绝不能只显示 `0 / 50`**：
   - sheet 只在「睡眠与心率至少有一项」时才出现（两项都缺时整行不渲染）；
   - 但**只缺一项**时（例如只有心率、没有睡眠），那一项会算 0 分，此时若显示 `睡眠 0 / 50`，用户会以为"我睡眠 0 分"——实际是**没有数据**；
   - **定死**：缺数据的项，分值显示 **「未同步」**（与首页数据条的窄容器标签口径一致），不显示 `0 / 50`；
   - 训练项永远有值（练过 20 / 没练过 6），不存在"未同步"。

> **这条是真空白，施工卡 §〇之三 的表格没写**。界面设计定的表格分值列固定为 `42 / 50` 形态，缺数据态必须补，否则用户被误导。

### 5.4 裁定：**「缺一项就不给分」这句说法必须改**

界面设计与文案稿都写的是"分数只按这三项算，缺一项就不给分"。**这句与代码实际行为不符，会让用户误解。**

代码实际行为（`ClubAIShell.swift:1424-1444`）：
- 睡眠、心率**都**没有 → 整行不渲染（这个才叫"不给分"）；
- 只缺**一项** → **该项按 0 分算，其余两项照常计分**，总分照样出；
- 训练项**永远有值**：练过 20 分，没练过 **6 分**（不是 0）。

**正确文案（三选一，都比原句准确）**：
- A：「就这三项相加。没同步到的那项按 0 分算，其余照常算。」
- B：「睡眠 50 分、心率 30 分、近三天练过 20 分。没同步到的那项按 0 分算。」
- C（最省字）：「三项相加。没同步的那项算 0 分。」

> **附带裁定**：训练项"没练过 = 6 分"这个设计**保留**（不是 bug），但 **6 分的来路必须在 sheet 里讲明**，否则用户看到"近三天练过 6/20"会以为系统在乱给分。建议行标签写「近三天练过」，解释句补一句"练过记 20 分，没练过也记 6 分"。

> **另一处必改**：行标签「睡够 7.5 小时」→「**睡眠**」。原标签读起来像"只有睡够 7.5 小时才给分"，实际是线性给分（睡 5 小时也有分），标签会误导用户。

### 5.5 缺陷：分项之和 ≠ 巨号总分（**现在就会红**）

**现象**：用户点开分项，自己把三项加起来，**跟巨号差 1 分**。

**根因**（`BojiClub/ClubAIShell.swift:1440`）：
```swift
let total = Int(min(100, max(0, sleepPoints + heartPoints + trainingPoints)))   // 对未取整的 Double 求和再截断
// 分项显示：
sleep: Int(sleepPoints.rounded()), heart: Int(heartPoints.rounded()), training: Int(trainingPoints)  // 各自取整
```
总分与分项**取整时机不同** → 分项相加可能比总分多 1。

**实测 12 组用例，3 组对不上**（例：睡 420 分 = 7 小时、心率 58、近三天没练过）：
- 分项显示 `47 + 30 + 6 = 83`
- 巨号显示 `82`（Double 和 82.67 截断）

**修法**：总分改由**已取整的分项**相加得出，三项与总分同源：
```swift
let sleepInt = Int(sleepPoints.rounded())
let heartInt = Int(heartPoints.rounded())
let trainingInt = Int(trainingPoints)
let total = min(100, max(0, sleepInt + heartInt + trainingInt))
```

**验收**：`BojiClubTests/CrossPageParityTests.swift` → `ReadinessScoreContractTests.testBreakdownComponentsSumToTotal`（12 组用例全绿）。

> 这条属于**一票否决**：用户自己能发现的算错，比缺功能更伤信任。
